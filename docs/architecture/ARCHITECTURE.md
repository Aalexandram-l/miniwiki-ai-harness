# MiniWiki — Архитектура проекта

## 1. Обзор проекта

MiniWiki — лёгкое веб-приложение для создания, редактирования, организации и поиска wiki-страниц.

Проект разрабатывается с использованием AI Agent Harness — среды разработки с ИИ-агентом, включающей правила проекта, контекстную память, повторно используемые навыки и автоматические проверки качества.

## 2. Технологический стек

- Язык программирования: Python 3.12
- Backend: FastAPI
- База данных: SQLite
- Работа с базой данных: SQLAlchemy
- Шаблонизация: Jinja2
- Интерактивность интерфейса: HTMX
- Стилизация: CSS
- Тестирование: Pytest
- Линтинг и форматирование: Ruff
- Контейнеризация: Docker

## 3. Архитектура приложения

Приложение использует модульную многоуровневую архитектуру.

- `app/main.py` — точка входа приложения.
- `app/routers/` — маршруты веб-приложения и API.
- `app/services/` — бизнес-логика.
- `app/models/` — модели базы данных.
- `app/templates/` — HTML-шаблоны.
- `app/static/` — CSS и статические ресурсы.
- `app/core/` — конфигурация, база данных и общая инфраструктура.
- `tests/` — автоматические тесты.

## 4. Основные возможности

- Создание и редактирование wiki-страниц.
- Просмотр и поиск страниц.
- Организация страниц с помощью тегов.
- Навигация между связанными страницами.
- Проверка и безопасная обработка Markdown.
- Предоставление REST API.
- Поддержка аутентификации и разграничения прав доступа.

## 5. Требования к качеству

- Автоматические тесты основной функциональности.
- Проверка входных данных и безопасная обработка пользовательского содержимого.
- Безопасное хеширование паролей.
- Единый стиль кода с помощью Ruff.
- Воспроизводимое окружение с использованием Docker.

## 6. Среда разработки с ИИ-агентом

Разработка поддерживается следующими компонентами:

- Rules — правила и ограничения проекта.
- Context Memory — долговременная контекстная память проекта.
- Skills — повторно используемые сценарии работы ИИ-агента.
- Checks — автоматические проверки кода и документации.

## 7. Принципы разработки

- Каждый модуль должен иметь чёткую ответственность.
- HTTP-обработка должна быть отделена от бизнес-логики.
- Интерфейсы должны быть явными и удобными для тестирования.
- Важные архитектурные решения необходимо документировать.
- Перед созданием коммитов следует запускать соответствующие проверки.
