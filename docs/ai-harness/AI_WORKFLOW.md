# Рабочий процесс AI Harness

## 1. Назначение

AI Harness — набор компонентов, обеспечивающих предварительную проверку пользовательских запросов, управление локальной памятью и формирование контекста для дальнейшей обработки.

На текущем этапе реализованы три основных компонента:

- Rule Engine;
- Memory Manager;
- Context Manager.

## 2. Общая схема работы

Обработка запроса состоит из следующих шагов:

1. Пользователь передаёт запрос.
2. Rule Engine проверяет запрос на соответствие заданным правилам.
3. Если запрос отклонён, дальнейшая обработка не должна выполняться.
4. Если запрос разрешён, Context Manager получает запрос и обращается к Memory Manager.
5. Memory Manager предоставляет сохранённые записи.
6. Context Manager формирует итоговый текстовый контекст.
7. Подготовленный контекст передаётся следующему компоненту приложения.

## 3. Взаимодействие компонентов

### Rule Engine

Отвечает за предварительную проверку пользовательского текста.

Основной метод:

- `check()` — возвращает результат проверки запроса.

### Memory Manager

Отвечает за хранение и получение информации.

Основные методы:

- `add()` — добавление записи;
- `get_all()` — получение всех записей;
- `get_by_category()` — фильтрация по категории;
- `delete()` — удаление записи.

### Context Manager

Отвечает за формирование контекста.

Основной метод:

- `build()` — объединяет пользовательский запрос и доступные записи памяти с учётом ограничения по символам.

## 4. Технологии

В реализации используются:

- Python 3.12;
- стандартная библиотека Python;
- JSON для локального хранения памяти;
- pytest для автоматического тестирования;
- Ruff для проверки качества и форматирования кода.

## 5. Структура проекта

Основные директории:

- `ai_harness/rules/` — движок правил;
- `ai_harness/memory/` — управление памятью;
- `ai_harness/context/` — формирование контекста;
- `tests/ai_harness/` — автоматические и интеграционные тесты.

## 6. Проверка качества

Для запуска всех тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

Для проверки качества кода:

```powershell
.\.venv\Scripts\python.exe -m ruff check ai_harness tests
```

Для проверки форматирования:

```powershell
.\.venv\Scripts\python.exe -m ruff format --check ai_harness tests
```

## 7. Текущие ограничения

AI Harness находится на стадии прототипа.

Текущая реализация:

- использует проверку правил по ключевым словам;
- хранит память в локальном JSON-файле;
- ограничивает контекст количеством символов;
- не подключает языковую модель;
- не выполняет семантический поиск по памяти.

Проверка Rule Engine не является полноценной системой безопасности и не заменяет авторизацию или специализированные механизмы защиты.

## 8. Дальнейшее развитие

В следующих версиях можно предусмотреть:

- расширенную систему правил;
- более надёжное хранение памяти;
- поиск релевантных записей;
- токенизацию и управление размером контекста;
- интеграцию с языковой моделью;
- расширенное логирование и мониторинг.
