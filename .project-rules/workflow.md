# Правила рабочего процесса

## Начало сессии

- В начале каждой рабочей сессии прочитать `docs/ai/PROGRESS.md`.
- Затем прочитать `docs/ai/PROJECT.md`.
- При необходимости изучить решения в `docs/ai/DECISIONS.md` и известные проблемы в `docs/ai/GOTCHAS.md`.
- Перед изменением кода изучить относящиеся к задаче файлы.

## Планирование

- Перед реализацией задачи сначала составить план (Plan).
- В плане перечислить цель, затрагиваемые файлы, последовательность действий и критерии проверки.
- Не начинать реализацию до определения плана.
- Не изменять файлы, не относящиеся к текущей задаче, без отдельного обоснования.

## Реализация

- Выполнять изменения небольшими логическими шагами.
- Сохранять существующий стиль и архитектуру проекта.
- Не добавлять зависимости без обоснования в `docs/ai/DECISIONS.md`.
- Не удалять существующий код без необходимости и объяснения.

## Проверка

- После каждой задачи запускать автоматизированные тесты командой `pytest`.
- Проверять качество кода с помощью Ruff, если изменения затрагивают Python-код.
- Исправлять обнаруженные ошибки до завершения задачи.
- Не создавать коммиты при проваленных тестах.

## Завершение сессии

- В конце каждой рабочей сессии обновлять `docs/ai/PROGRESS.md`.
- Фиксировать выполненную работу, незавершённые задачи и следующие шаги.
- Значимые архитектурные решения записывать в `docs/ai/DECISIONS.md`.
- Обнаруженные ошибки агента и способы их устранения записывать в `docs/ai/GOTCHAS.md`.
