# Правила безопасности

## Пароли

- Пароли пользователей хранить только в виде хешей.
- Для хеширования паролей использовать Argon2 или bcrypt.
- Запрещено хранить пароли в открытом виде.
- Запрещено записывать пароли в логи.

## Пользовательский HTML

- Весь пользовательский HTML необходимо очищать перед отображением.
- Не вставлять пользовательский HTML напрямую в страницы.
- Использовать проверенные средства очистки HTML.

## Работа с базой данных

- Все SQL-запросы должны быть параметризованными.
- Запрещено формировать SQL-запросы конкатенацией пользовательского ввода.
- Проверять и валидировать входные данные перед обработкой.

## Секреты и конфигурация

- Секреты хранить только в переменных окружения.
- Не добавлять реальные секреты, пароли и токены в Git.
- Файл `.env` не должен попадать в репозиторий.
- В репозитории разрешено хранить `.env.example` только с демонстрационными значениями.

## Общие требования

- Не отключать проверки безопасности ради прохождения тестов.
- Не ослаблять валидацию без документированного обоснования.
- При обнаружении уязвимости зафиксировать её и предложить исправление.
